# 拍卖直播秒杀中台

基于 Go + WebSocket + Redis 构建的高性能实时拍卖系统，已解决竞价超时、出价数据丢失等核心问题。

## ✅ 已修复功能

### 1. 竞价超时原子判断
- 使用 Redis `SETNX` 命令实现分布式锁，确保拍卖结束状态只被设置一次
- 防止多个请求同时触发拍卖结束逻辑
- 超时判断在服务端和出价时双重校验

### 2. 出价队列原子性操作
- 使用 Lua 脚本在 Redis 中原子执行出价入队操作
- 每个出价请求带唯一 `request_id`，防止重复提交
- 同一个请求不会被多次处理，确保数据一致性

### 3. 倒计时服务器推送 + 客户端本地校时
- 服务器每 500ms 推送倒计时和服务器时间
- 客户端接收服务器时间，计算本地时间偏差
- 本地计时器每秒递减，减少网络波动影响
- 实时显示时间同步状态（偏差秒数）

### 4. 用户预算校验
- 出价前检查用户预算是否充足
- 预算不足时直接拒绝请求
- 预算通过 Lua 脚本在 Redis 中原子操作
- 当用户出价被超越时，自动返还预算

## 快速开始

### 前置要求

1. 安装 Go 1.21+
2. 安装并启动 Redis（默认端口 6379）

### 启动步骤

1. **启动 Redis 服务**
```bash
# Windows
redis-server.exe

# Linux/Mac
redis-server
```

2. **启动拍卖服务**
```bash
go run cmd/server/main.go
```

3. **访问页面**
打开浏览器访问 `http://localhost:8080`

## API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/auctions` | 获取所有拍卖 |
| GET | `/api/auction/{id}` | 获取指定拍卖详情 |
| POST | `/api/auction/create` | 创建新拍卖 |
| POST | `/api/bid` | 提交出价（HTTP方式） |
| GET | `/api/deals` | 获取成交记录 |
| GET | `/api/user/balance` | 获取用户余额 |
| GET | `/ws` | WebSocket连接 |

### WebSocket 参数
```
/ws?client_id=<用户ID>&auction_id=<拍卖ID>
```

## WebSocket 消息类型

### 客户端 -> 服务器

```json
{
  "type": "bid",
  "payload": {
    "auction_id": "xxx",
    "user_id": "xxx",
    "username": "xxx",
    "price": 1000.0,
    "budget": 10000.0,
    "request_id": "timestamp-random"
  }
}
```

### 服务器 -> 客户端

| 类型 | 说明 |
|------|------|
| `bid` | 出价更新广播 |
| `timer` | 倒计时同步（含服务器时间） |
| `bid_result` | 出价结果反馈 |
| `auction_end` | 拍卖结束通知 |

## 核心数据结构

### Redis Key 设计

| Key 模式 | 类型 | 说明 |
|----------|------|------|
| `bid_queue` | List | 出价队列 |
| `auction:{id}` | String | 拍卖详情（JSON） |
| `bid_history:{id}` | List | 出价历史记录 |
| `deal_records` | List | 成交记录列表 |
| `user_balance:{user_id}` | String | 用户预算余额 |
| `bid_request:{request_id}` | String | 请求防重标记（10秒过期） |
| `auction_end_lock:{auction_id}` | String | 拍卖结束锁 |

### Lua 脚本

1. **出价入队脚本** - 确保请求不重复，原子入队
2. **预算校验脚本** - 原子检查预算并预留资金
3. **拍卖结束脚本** - 原子判断拍卖是否超时

## 使用说明

1. 启动服务后，系统自动创建演示拍卖（iPhone 15 Pro Max，5分钟）
2. 输入昵称，点击"连接拍卖"
3. 系统显示当前价格、倒计时、您的预算余额
4. 输入出价金额或点击快捷出价按钮

7. 拍卖结束后，最高出价者成功拍得商品，预算自动扣除

## 性能优化点

1. **高并发处理**: 每秒10次检查队列，批量处理出价
2. **原子操作**: 所有关键操作使用 Redis Lua 脚本保证原子性
3. **减少网络**: 客户端本地计时器 + 服务器增量推送
4. **防重机制**: 每个出价请求带唯一 ID，防止重复提交
5. **分布式锁**: 使用 SETNX 保证拍卖结束逻辑只执行一次

## 测试要点

1. **并发出价测试**: 多个用户同时出价，观察数据一致性
2. **网络延迟测试**: 模拟网络延迟，观察倒计时是否准确
3. **重复请求测试**: 同一请求重复发送，观察是否被正确拒绝
4. **预算边界测试**: 出价刚好等于预算、超过预算等场景
5. **超时并发测试**: 拍卖最后一秒多人出价，观察结束逻辑

## 常见问题

### Q: 为什么我的出价被拒绝？
A: 可能原因：
- 拍卖已结束或超时
- 出价未高于当前价格
- 预算不足
- 请求重复（网络重试导致）

### Q: 倒计时显示偏差怎么办？
A: 页面底部会显示时间偏差秒数。偏差在 5 秒内是正常的。偏差过大请检查网络连接。

### Q: 如何重置用户预算？
A: 系统默认每个用户初始预算 ¥10000。可以重启 Redis 服务或通过 Redis CLI 手动修改。

```bash
redis-cli SET user_balance:<user_id> 10000
```
