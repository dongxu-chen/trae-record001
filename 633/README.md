# ClickHouse 查询限流工具

一个基于查询复杂度的动态限流系统，支持熔断降级、用户级限流和查询优先级。

## 功能特性

### 🔒 动态限流
- **全局限流**：基于令牌桶算法的全局限流
- **用户级限流**：每个用户独立的限流配额
- **复杂度限流**：根据查询预估扫描行数和内存使用动态限流

### 🛡️ 熔断降级
- **熔断器模式**：失败率超过阈值时自动熔断
- **半开状态**：熔断超时后自动尝试恢复
- **快速失败**：熔断期间直接拒绝请求，避免资源耗尽

### ⚡ 查询优先级
- **三级优先级**：高/中/低优先级队列
- **加权调度**：高优先级查询获得更多执行机会
- **队列管理**：支持队列满时拒绝新查询

### 📊 查询分析
- **实时复杂度分析**：自动分析SQL复杂度
- **风险等级评估**：LOW/MEDIUM/HIGH/CRITICAL
- **资源预估**：预估扫描行数和内存使用

### 🔮 查询预测
- **实时资源预估**：提交前预测CPU、IO、网络、耗时
- **资源压力评估**：低/中/高/极高 四级压力标识
- **并发影响分析**：评估查询对整体系统的影响程度
- **提交前预警**：高风险查询提前给出警告和建议

### 👥 资源组隔离
- **独立配额**：每个资源组独立的限流、熔断、并发配置
- **资源隔离**：某个组熔断不影响其他组正常运行
- **权重分配**：支持多组资源按权重分配调度
- **默认配置**：data_team、reporting、realtime 三个预置组
- **动态管理**：支持运行时添加/删除资源组

### 🧪 限流演练
- **高并发模拟**：支持自定义并发数、QPS、持续时间
- **混合负载**：按比例混合简单/复杂/慢/错误查询
- **实时监控**：吞吐量、成功率、延迟分布等指标
- **演练报告**：P95/P99延迟、拒绝率、评估建议
- **一键启动**：支持快速默认配置和自定义配置

## 快速开始

### 前置要求
- Go 1.20+
- Node.js 18+
- ClickHouse 服务 (默认 localhost:9000)

### 启动后端

```bash
cd backend
go mod tidy
go run main.go
```

后端服务将在 `http://localhost:8080` 启动

### 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端服务将在 `http://localhost:3000` 启动

## API 接口

### POST /api/query
执行查询

**请求体：**
```json
{
  "user_id": "user_001",
  "query": "SELECT * FROM table",
  "priority": "medium"
}
```

### GET /api/status
获取系统状态

**响应：**
```json
{
  "CircuitBreaker": "closed",
  "QueueMetrics": {
    "total": 0,
    "high": 0,
    "medium": 0,
    "low": 0,
    "max_size": 1000
  },
  "QueryCount": 0
}
```

### GET /api/history
获取查询历史

### POST /api/analyze
分析查询复杂度

## 限流规则

| 规则 | 默认值 | 说明 |
|------|--------|------|
| 全局限流速率 | 10/秒 | 系统整体查询速率 |
| 全局突发量 | 20 | 瞬时最大查询数 |
| 用户限流速率 | 5/秒 | 单用户查询速率 |
| 用户突发量 | 10 | 单用户瞬时最大查询数 |
| 最大扫描行数 | 1亿 | 单查询最大扫描行数 |
| 最大内存 | 1GB | 单查询最大内存使用 |
| 查询超时 | 60秒 | 查询执行超时时间 |
| 熔断阈值 | 50%失败率 | 触发熔断的失败率 |
| 熔断超时 | 30秒 | 熔断后进入半开状态等待时间 |

### 渐进式恢复阶段

| 阶段 | 流量比例 | 成功数要求 | 最小持续时间 |
|------|----------|-------------|-------------|
| 探测阶段 (Probe) | 10% | 3次成功 | 5秒 |
| 低流量 (Low Traffic) | 30% | 5次成功 | 10秒 |
| 中流量 (Medium Traffic) | 60% | 8次成功 | 15秒 |
| 高流量 (High Traffic) | 90% | 10次成功 | 20秒 |

## 使用说明

### 查询执行
1. 打开前端页面 `http://localhost:3000`
2. 在查询执行页面输入 SQL 语句
3. 选择用户ID、资源组和查询优先级
4. 系统会自动分析查询复杂度并预测资源消耗
5. 查看CPU、IO、网络、耗时预测和资源压力评估
6. 点击执行查询，系统会根据限流规则决定是否执行
7. 在查询历史页面查看历史执行记录

### 资源组管理
1. 切换到"资源组管理"标签页
2. 查看所有资源组的实时状态（运行中、排队、熔断状态等）
3. 通过右侧表单创建新的资源组
4. 点击"删除"按钮移除不需要的资源组

### 限流演练
1. 切换到"限流演练"标签页
2. 点击"快速开始"使用默认配置开始演练
3. 或点击"自定义配置"设置并发数、QPS、持续时间等参数
4. 实时监控演练指标（成功率、拒绝率、延迟等）
5. 演练结束后查看完整报告，包含P95/P99延迟和评估建议
6. 点击"停止演练"可随时终止演练

### 系统状态
1. 切换到"系统状态"标签页
2. 查看全局熔断器状态和队列指标
3. 查看各个资源组的独立状态和指标
