## 核心数据结构

### 1. 锁等待事件 (lock_event)
```c
struct lock_event {
    u64 timestamp;        // 事件时间戳 (纳秒)
    u32 pid;              // 进程ID
    u32 tid;              // 线程ID
    u64 lock_addr;        // 锁地址
    u32 lock_type;        // 锁类型: FUTEX/MUTEX/RWSEM
    u32 event_type;       // 事件类型: WAIT_START/WAIT_END
    u64 wait_duration;    // 等待时长 (纳秒，仅WAIT_END有效)
    char comm[16];        // 进程名
};
```

### 2. 进程信息映射 (pid_info)
```c
struct pid_info {
    u64 start_time;       // 进程启动时间
    char comm[16];        // 进程名
    u32 is_mysql;         // 是否MySQL进程
};
```

### 3. 等待中的锁映射 (waiting_locks)
```c
struct waiting_lock {
    u64 start_time;       // 等待开始时间
    u64 lock_addr;        // 锁地址
    u32 lock_type;        // 锁类型
};
```

## 探针挂载点

| 探针类型 | 内核函数 | 用途 |
|---------|---------|------|
| tracepoint | sys_enter_futex | 捕获futex等待开始 |
| tracepoint | sys_exit_futex | 捕获futex等待结束 |
| kprobe | mutex_lock | 捕获互斥锁等待开始 |
| kretprobe | mutex_lock | 捕获互斥锁等待结束 |
| kprobe | down_read | 捕获读信号量等待 |
| kprobe | down_write | 捕获写信号量等待 |
| kretprobe | up_read | 读信号量释放 |
| kretprobe | up_write | 写信号量释放 |

## 死锁检测算法

基于等待图的实时环路检测：
1. 维护全局等待图 (TID → 持有锁的TID列表)
2. 每个锁等待事件触发局部DFS检测
3. 发现环路立即触发告警
4. 微秒级响应延迟
